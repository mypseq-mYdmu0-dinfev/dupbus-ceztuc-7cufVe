# hlint pairing-probe —— NOT a real query

*This is a PROBE FILE, not comms. It is deliberately shaped like a `query_` so that naming it in a prompt fires `cscpt/hlint.py`'s query/response pairing reminder. It carries a far-future timestamp (`209912312359`) so it can never collide with a real comms file, and it lives in `cp/ccsim/sandbox/` so it is never mistaken for one. Nothing reads its contents.*

## How to Use It

Submit a prompt whose text is exactly this filename, bare and unbackticked:

`ccsim_query_209912312359.md`

ALIVE looks like: an `[hlint hook] Query/response pairing` line arrives in context naming `ccsim_response_209912312359.md` as the response that query owes.

DEAD looks like: nothing at all. There is no third outcome —— the check is silent only when the owed response exists, and no `ccsim_response_209912312359.md` may ever be created beside this file.

## Why It Is Load-Bearing

`cp/ccsim/hook_guide.md` §7.1 states the distinction this file exists to serve: "the script works when I pipe it a payload" tests the SCRIPT, whilst "the harness actually invokes it" tests the WIRING, and only the second delivers any value. Piping a payload into `hlint.py` by hand proves nothing about whether `UserPromptSubmit` still reaches it. This probe is the only way to test that arm through the real path, because a sub-agent cannot submit a user prompt.

Three properties make it work, and all three must be preserved:

- The `query_` in the name is what the pairing check matches on. Rename it and the probe stops probing.
- It must be the NEWEST `ccsim_`-prefixed query in this folder, which a far-future TS guarantees permanently.
- It must never acquire a sibling `ccsim_response_209912312359.md`, which would silence the check by design.
