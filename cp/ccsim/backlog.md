## `universal/glossary.md` vs `universal/sprint.md` —— FOF's all-at-once override is declared on ONE side only
Problem: The two files give opposite instructions on the same decision, and only one of them admits it. `glossary.md` (§ Terms, `FOF` entry) defines FOF as "use Workflow tool w/ all-at-once fleet", then adds its own carve-out —— "This overrides `sprint.md`'s 'NEVER one all-at-once fleet...'" —— justified by "Usually means ses% = 0, hence sesL is unlikely to kill SAs mid-flight". `sprint.md` (§ `#sprint` —— Time Abundant, the Workflow bullet) states the reverse as an absolute: "MANDATE wave-staging INSIDE the script —— bounded sequential batches, NEVER one all-at-once fleet", citing root `CLAUDE.md` §9.02.4 (a sesL kills them together; partials are compromised). `sprint.md` never mentions FOF, the glossary, or any exemption —— yet the same file DOES spell out a different override elsewhere ("A sprint also overrides the 'request/await confirmation' steps of OTHER protocols"), so the silence is an inconsistency rather than house style. Consequence: an agent mid-`#sprint` reads `sprint.md` and sees an unconditional ban, whilst an agent that happened to look FOF up sees a licence to fan out all at once; which rule governs is settled by whichever file that agent happened to open, i.e. arbitrarily at runtime (`universal/coding.md` § Prompted Components —— an unstated conflict is a coin-flip). The glossary's trigger is also soft ("Usually" ses% = 0), so it leaves the case where that is false undecided.
Suggestion: Owner's call —— both files sit outside CCSIM's default ownership here and the correct answer depends on which behaviour is actually wanted, so this is logged rather than fixed. Two candidates: (a) KEEP the override and back-reference it from `sprint.md`'s Workflow bullet in one clause, so the exemption is visible to the agent who only reads `sprint.md`, and replace "usually ses% = 0" with a condition that can actually be checked before fanning out; or (b) DROP the override, letting wave-staging govern FOF too, and delete the glossary's carve-out line. (a) is the cheaper edit and preserves the stated intent; either way both files must end up stating the same rule.
Ref: `universal/glossary.md` § Terms (FOF entry); `universal/sprint.md` § `#sprint` —— Time Abundant (Workflow bullet); root `CLAUDE.md` §9.02.4
