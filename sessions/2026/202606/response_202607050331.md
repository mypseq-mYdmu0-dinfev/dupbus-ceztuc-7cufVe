*Nesting depth doesn't matter here*

1. Verdict: Same (near-zero) risk either way —— nesting under `AJAP_dir/` doesn't add protection in your actual setup
- 1.1. Confirmed via Anthropic's official docs (supersedes my inferred caveat in response_202607050306.md): the on-demand subdirectory `CLAUDE.md` loader ONLY fires for directories nested UNDER the current session's working directory (CWD)
- 1.2. `AJAP_repo/` is a SIBLING of `dupbus-ceztuc-7cufVe/` (this repo), not a descendant of it —— so when this repo's CC does an absolute-path `Read` into `AJAP_repo/...`, that on-demand mechanism never engages at all, regardless of how deep the file sits
- 1.3. So `AJAP_repo/CLAUDE.md` (root) and `AJAP_repo/AJAP_dir/CLAUDE.md` (nested) are equally safe under normal absolute-path browsing —— neither auto-loads into this repo's sessions

2. When nesting WOULD start to matter (i.e. genuine risk re-appears):
- 2.1. If this repo's CC ever `cd`s into (or otherwise makes its CWD) somewhere inside `AJAP_repo/` —— then it behaves like a normal CC session rooted there, and root-level `CLAUDE.md` loads at launch whilst nested `AJAP_dir/CLAUDE.md` only loads on-demand (i.e. nesting DOES help in that scenario)
- 2.2. If `AJAP_repo/` is ever added via `--add-dir` WITH `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` set (non-default) —— same as 2.1
- 2.3. If the Claude app's own "add folder to session" feature behaves like 2.2 (uncertain —— docs don't confirm the app UI's exact internals; this is the case this repo's own `c.md` §1.2 guards against for ITS OWN root)

3. Practical takeaway:
- 3.1. Current setup (sibling repo, absolute-path `Read` only) is already safe by construction —— you don't strictly need the nesting for this specific concern
- 3.2. Keep nesting anyway as free belt-and-braces (costs nothing, helps in the 2.1–2.2 edge cases)
