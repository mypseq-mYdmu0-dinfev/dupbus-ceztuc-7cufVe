# Response to query_202607050306.md
*AJAP: new repo won't inherit c.md*

1. Verdict: No, a new dedicated AJAP repo would NOT unintentionally read this repo's root `c.md`, provided you never add this repo as a session folder.
- 1.1. CC's CLAUDE.md discovery walks the filesystem from the session's working directory upward to the filesystem root, loading every `CLAUDE.md`/`CLAUDE.local.md` it finds along that ancestor chain
- 1.2. Subdirectory `CLAUDE.md` files are loaded on-demand only when CC accesses files inside that subdirectory tree (i.e. within the same project)
- 1.3. `--add-dir` (or dragging a folder into session) explicitly adds another directory's ancestor chain into scope —— this is the exact mechanism §1.2 of this root `c.md` already names ("when root folder is added")

2. Applied to your scenario:
- 2.1. If AJAP's new repo is the session's sole working directory, and it Reads a single file via absolute path (e.g. `seek/context/culous_yu_portfolio.md`) from THIS repo, that's a plain file read —— not a directory-scope addition
- 2.2. A file read via absolute path outside the CWD's own tree shouldn't trigger this repo's ancestor `CLAUDE.md` chain (this repo's root `c.md` sits several directories above that file, but AJAP's CWD ancestry doesn't pass through it)
- 2.3. Risk cases that WOULD pull this repo's `c.md` in:
  - 2.3.1. Manually adding this repo as a folder to the AJAP session (UI drag-in or `--add-dir`)
  - 2.3.2. AJAP `cd`-ing or globbing/exploring broadly within this repo's tree (rather than a single targeted absolute-path Read)

3. Caveat (per §2.8.4):
- 3.1. The general mechanism (2.1–2.2) is confirmed by Anthropic's docs; the SPECIFIC edge case "single absolute-path Read of an external repo's file, without adding its folder" isn't explicitly called out in what I found —— it's my inference from the documented rules, not a directly-confirmed line item
- 3.2. Recommend empirically verifying once the new repo exists: start a fresh session there, have it Read the 1 external context file, then check (e.g. ask it directly, or inspect session cost/transcript) whether this repo's `c.md` loaded
