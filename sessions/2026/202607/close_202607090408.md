## 2. Decisions

- 2.1. Git-history doctrine (general, learnt from a real loss): git stores NO renames —— every view re-detects by content similarity, so a move must be a move-ONLY commit (edit → commit → `git mv` → commit); rename+edit in one commit can fall below every threshold and break GH's history view.
- 2.2. GH's file-history view can fabricate lineage: for one dissertation file its 15 "extra" commits were proven to be an unrelated file's history chained via two ~0%-similarity hops —— git_history.py now matches-or-beats GH whilst labelling such guesses.
- 2.3. Engineering lesson (portable): when a new single source of truth appears, re-derive consumers FROM it instead of patching their old inputs; and consumer docs/code should carry self-contained rationale, never references into comms files.
