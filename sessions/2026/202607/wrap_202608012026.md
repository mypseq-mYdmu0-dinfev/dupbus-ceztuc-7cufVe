## 2. Decisions
- 2.1. Hooks live in user settings, fail open
  - 2.1.1. Hooks are registered permanently in `~/.claude/settings.json`; project-level registration was removed so a future Desktop fix cannot double-fire (a recoverable copy sits at `.claude/hooks_user_settings.reference.json`)
  - 2.1.2. Every lint self-scopes via the payload `cwd` and fails OPEN —— a silently disabled lint was the exact failure the session was about
  - 2.1.3. `hlint` and `tlint` were deliberately globalised (advisory only, safe anywhere) so AJAP sessions benefit; `clint`/`dlint`/`nlint` stay repo-scoped because they enforce this repo's conventions
  - 2.1.4. `tlint` exempts only co-located {query,response} or {close,artefact} pairs and checks the cross-repo mirror within the same year-month; at `~`38ms it is always-on, never skipped
  - 2.1.5. `clint` was demoted to warn-only at the user's instruction —— enforcement now rests on the turn-end rules, not the hook
- 2.2. Chat prose controlled by glyph ownership
  - 2.2.1. Glyph ownership is the primary mechanism; word and character caps are only a final net
  - 2.2.2. The character limit is kept invisible to CC, because a visible limit is one it will spend up to
  - 2.2.3. A block message should REDIRECT swallowed content into the `response_`, not merely forbid it
  - 2.2.4. Mechanism constraint learnt the hard way: a Stop hook's `systemMessage` and exit-0 output reach only the user —— only exit-2 stderr reaches CC, and must be guarded by `stop_hook_active` to cap it at one extra turn
- 2.3. Root CLAUDE.md doctrine codified
  - 2.3.1. TEA ordering fixed —— all tasks → commit and push → chapter marker → declarations, so clicking the marker lands on the declarations
  - 2.3.2. §3.1.7.6 now defines a practical turn, and §3.1.8 adds the Harness Nudge (a harmless tool call first, a lone `.` only as last resort)
  - 2.3.3. Push classification: CC-only changes → commit and push; CC changes plus user edits elsewhere → push CC-touched files only; user edits on CC-touched files → alert, do not commit
  - 2.3.4. Narrow git allow-rules added so the turn-end push escapes classifier gating —— explicitly NOT `Bash(git *)`, which auto mode drops as arbitrary execution
  - 2.3.5. `/loop` and timed wakes must use a persistent Monitor sleep-loop, never CronCreate —— cron fires only on an idle REPL, so busy sessions starve it silently (live-proven twice)
  - 2.3.6. SAs carve themselves out of root `CLAUDE.md` via a one-line disregard notice, and MA must state "You're a sub-agent" in every dispatch
  - 2.3.7. `#sync` now aborts loudly on a path missing from the working tree, instead of pinning a renamed-away file to the commit that deleted it
- 2.4. Redundancy kept where mechanisms fail differently
  - 2.4.1. Root `CLAUDE.md` §7.2 was kept despite the skills layer —— §7.2 is a guaranteed read, a skill match is probabilistic, so the redundancy is cover
  - 2.4.2. Two usage scripts kept on purpose (zero-dependency standalone vs venv module) with sibling mirror-notes in both, rather than merged
  - 2.4.3. The dark-mode split separates what is REQUIRED (a 71tk pointer in `coding.md`) from HOW to build it (978tk in `cscpt/dark_mode.html`), saving `~`907tk per non-HTML session
- 2.5. Moves must be move-only commits
  - 2.5.1. Sequence is edit → commit → `git mv` → commit; a rename-plus-edit in one commit can fall below every similarity threshold and destroy the history view
  - 2.5.2. `git_history.py` therefore matches or beats GitHub's rename-following whilst amber-labelling every structural guess it makes
  - 2.5.3. The retired `seek/` tree was kept read-only under `backup/` with recursive `backup_` prefixing for global-search hygiene, rather than deleted
  - 2.5.4. `nscpt/git_move_batch.py` was judged per-commit-hygiene SAFE but unfit as-is for the `cp/` migration
- 2.6. Migration pattern mandated after the CAI scare
  - 2.6.1. SAFE MIGRATION PATTERN is now mandatory (`ssd_migration_guide.md` §7): force-quit and verify → ditto → verify count and bytes → RENAME ASIDE (`mv`, never `rm` before the symlink) → symlink → keep backups
  - 2.6.2. CAI was migrated now rather than deferred to the APFS reformat —— justified by the UPS, FURY's 3-year record, the hardened v2 script, integrity-scanning recovery, and the mount guard; surprise-unmount SQLite risk is mitigated, not eliminated
  - 2.6.3. Meta-lesson: OVER-GUARDING (crashpad process kills, `lsof` checks) caused more failures than it prevented —— the simple proven rescue set was the correct approach
- 2.7. Sizing and capacity measured, not estimated
  - 2.7.1. pcmd size and trim figures must be reported in tokens, never words —— written into `coding.md` after correcting an earlier response
  - 2.7.2. Two sesL data points recorded: `~`346.4k tokens ≈ 20% of an Opus session, and a measured turn moving ses% 0 → 17 on `~`1.26Mn newly-processed tokens, implying `~`7.4Mn per 100 ses%
  - 2.7.3. Both are single observations —— calibrate against observed ses% and do not assume a clean 2×/0.5× for Sonnet or Fable
- 2.8. Style, evidence weighting, and brand fixed
  - 2.8.1. `#style` is a MODIFIER (a column) layered on a manner row (Casual/Professional/Academic), never a manner swap, so the existing matrix stays intact
  - 2.8.2. Style content lives in a separate `writing_style.md`, mirroring the `cic.md`/`cic_bot.md` split, to keep `writing.md` lean
  - 2.8.3. Evidence weighting for voice inference: the user's own critiqued drafts > his resignation letters and site copy (context-dependent) > third-party research (illustrative only, never blanket-applied)
  - 2.8.4. Standing rule —— extract the gist and rationale from example-based feedback, never hard-code the specific word or example, unless told to ban it outright
  - 2.8.5. Brand palette adopted as the default for any design or visual output: dark teal `#005166`, mid teal `#468EA1`, light teal `#20898A`, and fire-red Arancio Xanto `#E64A37`
- 2.9. Career and dissertation calls worth reusing
