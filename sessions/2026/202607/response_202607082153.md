# Response to query_202607082153.md
*Decoy Focus Confirmed Viable; Script Built*

1. Verdict: YES, it works, and it's cleaner than a raw "override" —— fully legitimate macOS mechanism, no hacking/spoofing needed.

2. Why it works (verified via 2 independent angles —— Apple dev docs AND Apple support docs agree):
- 2.1. The Focus-status API apps like Avast query (`isFocused`, gated by the permission you already granted it) is a BARE boolean —— "is any Focus active", with zero visibility into what that Focus does or doesn't silence. So a Focus that blocks nothing can still report "active" to Avast.
- 2.2. The trick: for a custom Focus's Apps row AND People row, switch the mode from "Allow Notifications From" (whitelist, brittle —— what you were worried about) to **"Silence Notifications From"** and add NOBODY to either list. Empty blacklist = nothing gets silenced, ever, incl. apps you install later —— confirmed by Apple's own support guide + community threads.

3. One-time setup (manual, GUI —— cannot be scripted, Apple provides no CLI/API to create Focus configs):
- 3.1. System Settings ▸ Focus ▸ `+` ▸ Custom ▸ name it e.g. "Avast Decoy"
- 3.2. Inside it: Apps row → "Silence Notifications From" → add nothing; People row → same → add nobody
- 3.3. Turn it ON once; approve Avast's Focus-status permission prompt when it appears (or grant via System Settings ▸ Privacy & Security ▸ Focus ▸ Avast)
- 3.4. In Avast ▸ Preferences ▸ Notifications tab, ensure "Disable notifications when in Focus mode" is checked (from `response_202607082146.md` §4.1)
- 3.5. Verify: other apps' banners still appear normally whilst this Focus stays on

4. Re your "firmware update might wipe our override" worry —— reassuring correction: this concern doesn't actually apply. The Focus configuration lives entirely inside macOS's own protected store (outside any app's sandbox, owned by system daemons) —— Avast has no access path to it at all, so an Avast update literally cannot touch it. The only realistic way it gets turned off is YOU (or something else) toggling it off by accident.

5. Script built anyway, since you asked for a "redo" mechanism —— `nscpt/avast_focus_reenable.sh`:
- 5.1. It does ONE thing: re-run a Shortcuts.app shortcut that turns your "Avast Decoy" Focus back on —— this covers the realistic case (accidental toggle-off), even though the update-wipe case (4) turned out to be a non-issue
- 5.2. It CANNOT create/configure the Focus itself —— Apple exposes no scriptable way to author Focus configs, only to toggle an already-existing one via Shortcuts' "Set Focus" action + `shortcuts run "<name>"` CLI. So: build the Shortcut once (steps in the script's own top comment), then this script is your one-line "put it back on" button, editable at the top if you rename either the Focus or the Shortcut.
- 5.3. Not run/tested by me (nothing to test yet —— it depends on the Focus + Shortcut existing, both from your manual step 3 above); tell me once you've done 3 and I'll verify the script actually fires it.

Nothing else (Handoff, Reminders badges, etc.) was found to be affected.
