# Response to query_202608041738.md
*GH Repo Privacy & OTGC Access*

## 1. Problem 1 —— Public Repo Risk
- 1.1. Confirmed real: on a personal-account repo, `github.com/<username>/<repo>` is shown to anyone w/ access
- 1.2. Structural, not a bug —— no toggle hides it on a personal repo

## 2. Problem 2 —— Did Anthropic Fix OTGC Private-Repo Access?
- 2.1. Unclear; lean negative-to-uncertain
- 2.2. Anthropic's docs describe private-repo access as supported by design (OAuth GitHub App connector, NOT a PAT field)
- 2.3. Real-world bug reports run into Jul`~`Aug 2026: a Jun 2026 regression broke content access for ANY repo; silent sync failures on private repos; a Jul 2026 issue even claimed the web/mobile app has no GitHub connector at all (closed "not planned", ambiguous)
- 2.4. No dated Anthropic changelog says "private repos now fixed"; nothing confirms iOS Chat-tab parity specifically (inferred from shared backend, not verified)
- 2.5. Confidence: medium-low

## 3. Problem 3 —— Hiding Username & Single-File Sharing
- 3.1. Hiding username: partially yes, only via structural workaround
  - 3.1.1. Move repo to a GitHub Organisation —— `github.com/<org>/<repo>` replaces your username in the visible owner/URL
  - 3.1.2. Grant access via org teams rather than adding yourself as a visible collaborator
  - 3.1.3. Caveats that still leak identity: commit authorship (name+email), PR/issue comments, org-admin visibility to other admins
  - 3.1.4. No Google-Drive-style anonymous share link exists on GH
- 3.2. Single-file-only sharing: no native GH feature does this (confirmed via GH's own community forum —— "not possible in a built-in way")
  - 3.2.1. Closest workaround: GitHub Releases —— attach file as a release asset on an org-owned repo (private repo still needs recipient auth token)
  - 3.2.2. Alt: GitHub Pages —— serve just that file publicly from `<org>.github.io/...`, no GH account needed by recipient
  - 3.2.3. Gists do NOT solve this —— always tied to your personal username; "secret" gists are link-accessible-by-anyone, not truly private
  - 3.2.4. 3rd-party bridge (`over-sharer`) exists but Markdown-only & needs OAuth trust —— not independently verified

## 4. Recommendation

- 4.3. Sequence: test OTGC on `AJAP_repo/` first (§5) → only if clean, flip default repo to private → separately pursue org-ownership for the username concern (independent of public/private choice)
