## Why This Is Worth Fixing (diagnosis per `cp/ccsim/CLAUDE.md` §8.7)
- NOT-NOTICED vs misapplied: this reads as NOT-NOTICED (an enforcement gap), not a misreading of the words. CC's own reasoning earlier in the same turn correctly laid out the full m2 sequence including "then proceed to #sprint" —— the rule was understood in the abstract. But at the exact moment the final message was assembled, it ended on bare declaration text with no trailing tool call, which is EXACTLY the shape that root §3.1.7.5 trains as "turn over" everywhere else in this protocol (TEA3 is always, without exception, the last thing in a turn). m2.md's one narrow exception to that pattern didn't survive contact with the much stronger, repeated general pattern.
- Per §8.7: "the prose that failed cannot repair it —— bolding, repeating, or relocating words that were already skipped changes nothing while feeling like a fix." Rewording m2.md's "the turn does NOT end here" more emphatically is unlikely to fix a recurring, cross-session miss —— the words are already unambiguous, and were already read this session.
- This is exactly the shape of gap CCSIM's Operating Posture (§8.1) targets: "a rule that only works if someone recalls it at the right moment has already failed."

## Candidate Fix Directions (for the receiving session to weigh, not decided here)
1. Make m2.md's step 2 structurally impossible to end a turn on: instruct that the interim declare line must NEVER be the last content of a message —— it must be immediately followed, in the SAME message, by the next mandated tool call (e.g. reading `universal/sprint.md`, per step 3). This mirrors root §3.1.8's existing "Harness Nudge" mechanism (a harmless tool call to avoid a bare-text stop) —— reuse that pattern here rather than inventing a new one.
2. A lint/hook angle: if feasible, a lightweight check specific to `#m2`/`#sprint` turns that flags (non-blocking) an assistant message containing ONLY the `➡️` declare with no subsequent tool call queued —— though this may be hard to implement outside the model's own turn-generation, unlike root's existing file-based hooks.
3. If neither is buildable, at minimum record this as a known, recurring miss directly in `m2.md` itself (not just here), phrased as a runtime trip-wire ("if you notice yourself about to end the message right after the declare line, that IS the failure mode —— queue the next tool call now") rather than a restatement of the rule —— though per §8.7 this is the weaker fix (still prose-based); directions 1–2 are preferred.
